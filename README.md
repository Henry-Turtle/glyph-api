# Navidrome with Sidecar API

This project contains a lightweight "Sidecar" REST API deployed alongside an instance of [Navidrome](https://www.navidrome.org/). It runs in the background and processes ID3 metadata updates for track files managed by Navidrome.

## Overview

Navidrome is heavily deployed using Docker containers. Because the Sidecar Go application needs to manipulate the precise paths that are registered inside Navidrome's database, the easiest way to ensure parity is to run both services together using Docker Compose.

Both services mount the exact same `music` folder.
- **Navidrome** indexes the files and reads them.
- **Sidecar API** safely writes updated ID3 tags.

## Prerequisites
- Docker and Docker Compose installed on your host system.
- This codebase pushed to your own GitHub repository.

## Installation via Pre-built Image

The best way to run this is by using the pre-built Docker image automatically generated by GitHub Actions. 

1. **Publish Your Image**: A hidden GitHub Actions workflow (`.github/workflows/publish.yml`) is included in this repository. Ensure this project is pushed to your GitHub account. Every time you push to the `main` branch, GitHub will automatically build and publish your Docker image to the GitHub Container Registry (GHCR) for free.
2. In your `docker-compose.yml` file, replace `Henry-Turtle/glyph-api` with your actual GitHub username and repository if you move this project.
3. Replace the `API_KEY` placeholder with a secure password. 
4. **Configuration**: You can optionally configure `MAX_DOWNLOAD_WORKERS` to control how many `yt-dlp` tasks run concurrently (defaults to `3`, capped at `10`). Metadata spot-edits are handled instantly regardless of this limit.
5. Ensure you have the `/music` volumes pointing to your actual host music directory.

Start the instance in the background by running:
```bash
docker-compose up -d
```

## Keeping the Image Automatically Up to Date

If you push updates to your API on GitHub, a new Docker image will be published. To ensure the sidecar running on your machine automatically detects and pulls this new image, it is highly recommended to use **Watchtower**.

Watchtower is a tiny companion tool that monitors your running Docker containers. When a new version of the Sidecar API image is published to GitHub Container Registry, Watchtower will safely stop the old container, download the new image, and bring up the container exactly as it was.

**Preventing Daytime Outages**: To prevent Watchtower from randomly restarting your Sidecar API while you are actively using Navidrome, it has been configured to use a strict schedule. Instead of checking randomly throughout the day, Watchtower is set to only check for updates and perform restarts strictly at **4:00 AM** every day. 

You can see this setup in the `docker-compose.yml` block below:

```yaml
  watchtower:
    image: containrrr/watchtower
    container_name: watchtower
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      # Use cron syntax: Seconds Minutes Hours DayOfMonth Month DayOfWeek
      # This schedules checks for 4:00 AM every single day to prevent disruptions
      - WATCHTOWER_SCHEDULE=0 0 4 * * *
    restart: unless-stopped
```

Alternatively, you can skip Watchtower and manually pull the latest updates anytime by running:
```bash
docker-compose pull
docker-compose up -d
```

## Usage

The Sidecar exposes two main REST endpoints that you can call with the `X-API-KEY` header matching your environment variable.

### 1. Update Existing Track Metadata
Use the `/update-track` endpoint by sending a POST request to port `8080`. The `file_path` you send in the payload must be the absolute container path that Navidrome uses (e.g., `/music/Path/To/Track.mp3`).

```bash
curl -X POST http://localhost:8080/update-track \
  -H "X-API-KEY: my-super-secret-api-key" \
  -H "Content-Type: application/json" \
  -d '{"file_path": "/music/Path/To/Track.mp3", "title": "New Title", "artist": "New Artist"}'
```

### 2. Download New Track from YouTube
Use the `/download-track` endpoint to asynchronously fetch audio using `yt-dlp`. It accepts a `url`, a `quality` parameter (`max`, `mid`, or `low`), and optional metadata tags (`title`, `artist`, `album`). The API will return immediately with a `202 Accepted` while the download completes in the background.

```bash
curl -X POST http://localhost:8080/download-track \
  -H "X-API-KEY: my-super-secret-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ", 
    "quality": "max", 
    "title": "Never Gonna Give You Up", 
    "artist": "Rick Astley",
    "album": "Whenever You Need Somebody"
  }'
```
